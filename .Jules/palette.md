## 2025-03-05 - Disabled Button Explanations & Native Tooltips
**Learning:** HTML `disabled` attributes inherently cause elements to be removed from the focus order and they swallow pointer events in most browsers. This means that a standard `title` attribute directly on a `<button disabled>` will not render a tooltip on hover, and the element will be completely invisible to screen readers navigating by tab, leading to poor UX and accessibility for conditionally unavailable actions.
**Action:** When a button is conditionally disabled, wrap it in a `<span>` element. Apply the `title` explaining the disablement to the `span`. Conditionally apply `tabIndex={0}` to the wrapper *only* when the child button is disabled (e.g., `tabIndex={isDisabled ? 0 : undefined}`). This ensures screen readers and keyboard users can discover the state and reason without introducing an annoying double tab-stop when the button is enabled. Ensure layout integrity is preserved by applying appropriate flex/grid sizing classes (e.g., `inline-flex w-full` on the wrapper, `w-full` on the button).
